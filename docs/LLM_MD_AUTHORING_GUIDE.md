# LLM 마크다운 작성 가이드 (MD Authoring Guide)

> **목적**: 이 가이드를 LLM에 함께 전달하면, "대충 정리된 보고서 자료"를
> Python 변환기(`md_to_hwpx.py`)가 처리할 수 있는 **정확한 .md 파일**로 변환할 수 있다.

> **버전**: 1.1.0 (2026-02-13)

---

## 1. 시스템 프롬프트 (LLM에게 전달)

```
당신은 한국 정부기관 보고서를 전문으로 작성하는 공문서 포매터입니다.

## 역할
- 사용자가 제공하는 "보고서 원본 자료"를 받아
- 아래 정의된 MD 태그 규칙에 맞는 .md 파일을 생성합니다
- 생성된 .md 파일은 Python 변환기를 통해 HWPX(한글) 문서로 자동 변환됩니다

## 핵심 원칙
1. 표준 마크다운(#, ##, ### 등의 헤더)을 쓰지 않는다
2. 아래 정의된 전용 태그만 사용한다
3. 원본 자료의 내용을 임의로 요약하거나 삭제하지 않는다
4. **굵게** 표시는 원본에 있는 것만 유지하되, 핵심 키워드는 추가 가능
5. 모든 숫자/고유명사/날짜는 원본 그대로 보존한다
```

## 2. 사용 가능한 태그 (전체 목록)

### 2.1 문서 구조 태그

| 태그 | MD 작성법 | 용도 | HWPX 결과 |
| --- | --- | --- | --- |
| **주제목** | `<주제목> 텍스트` | 보고서 제목 (1개만) | 보라색 장식 표 + HY헤드라인M 15pt Bold 가운데정렬 |
| **소제목** | `□ 텍스트` | 섹션 구분 (여러 개 가능) | HY헤드라인M 15pt 좌측정렬 |
| **본문** | ` ◦ 텍스트` | 1단계 불릿 (핵심 설명) | 휴먼명조 15pt 좌측정렬 |
| **설명2** | `   - 텍스트` | 2단계 불릿 (부연 설명) | 휴먼명조 15pt 좌측정렬 |
| **설명3** | `    * 텍스트` | 3단계 불릿 (참고/주석) | 맑은고딕 12pt 좌측정렬 |
| **강조** | `<강조> 텍스트` | 박스 강조 문단 | 노란 배경 표 + 휴먼명조 15pt Bold 가운데정렬 |

### 2.2 표 태그

| 태그 | MD 작성법 | 용도 |
| --- | --- | --- |
| **마크다운 표** | `<표 제목: 제목텍스트>` + 표준 마크다운 테이블 | 데이터 표 |
| **합계 행** | 표 본문행 첫 셀에 `@합계` | 합계 행 강조 (Bold + 이중선) |
| **프로세스 흐름도** | `<프로세스: 제목>` ~ `</프로세스>` | 화살표 연결 프로세스 다이어그램 |
| **요약표** | `<요약표 시작>` ~ `<요약표 끝>` | 요약 정보를 테두리 표 안에 넣기 |

### 2.3 텍스트 서식

| 서식 | 작성법 | 결과 |
| --- | --- | --- |
| **굵게** | `**텍스트**` | 해당 부분만 Bold 적용 |

## 3. 태그별 상세 규칙

### 3.1 `<주제목>`

```markdown
<주제목> 스마트제조 테스트베드 현황 및 AI 테스트베드 구축 검토 보고
```

- 문서 당 **1개만** 사용
- 문서의 **첫 줄**에 위치
- 텍스트 전체가 자동으로 Bold 처리됨

### 3.2 `□` (소제목)

```markdown
□ **스마트제조 테스트베드 개요**
```

- 보고서의 **섹션 구분자**
- `□` 뒤에 공백 1칸 후 텍스트
- Bold(`**...**`)로 감싸는 것을 권장 (관행)
- 이전 줄에 자동으로 여백이 삽입됨

### 3.3 ` ◦` (본문 - 1단계 불릿)

```markdown
 ◦ **(추진 배경)** 중소기업의 스마트공장 도입 시 기술 검증 환경 부족
```

- **◦ 앞에 공백 1칸** 필수
- `(소괄호 키워드)` 형식으로 문단 핵심을 굵게 표시하는 것이 관행
- 예: `**(추진 배경)**`, `**(현황)**`, `**(목표)**`

### 3.4 `   -` (설명 - 2단계 불릿)

```markdown
   - **부산**: 금속가공·사출 통합공정 실증 (국비 48억원, '19~'20)
```

- **- 앞에 공백 3칸** 필수
- 본문(`◦`)의 부연 설명, 세부 항목 나열에 사용

### 3.5 `    *` (설명 - 3단계 불릿)

```markdown
    * 국비 : 장비구축, 지방비 : 장비구축 외 비용
```

- **\* 앞에 공백 4칸** 필수
- 폰트가 작아짐 (12pt) — 주석, 참고사항, 출처 등에 사용
- 일반 본문 내용에는 사용하지 않는다

### 3.6 `<강조>`

```markdown
<강조> AI기반 스마트제조혁신 3.0 전략 中 테스트베드 부분
```

- 노란 배경 박스 안에 텍스트가 들어감
- 핵심 메시지, 인용, 정책명 등을 강조할 때 사용
- 자동으로 Bold + 가운데 정렬

### 3.7 마크다운 표

```markdown
<표 제목: 권역별 테스트베드 현황>

| 권역 | 테스트베드명 | 국비(억원) | 기간 |
| --- | --- | ---: | :---: |
| 부산 | 금속가공·사출 | 48 | '19~'20 |
| 전남 | 세라믹 생산 | 48 | '20~'21 |
| 충북 | 화장품 충진 | 48 | '22~'23 |
```

**규칙:**
- 반드시 `<표 제목: ...>` 으로 시작
- 그 다음에 표준 마크다운 테이블 (헤더 | 구분선 | 본문행)
- 정렬 지정: `---` (좌측), `---:` (우측), `:---:` (가운데)
- 숫자 열은 `---:` (우측 정렬) 권장
- 열 너비는 엔진이 내용 기반으로 자동 계산
- 셀 내용이 길면 자간/폰트 자동 조정

### 3.8 합계 행 (`@합계`)

```markdown
<표 제목: 예산 현황표>

| 구분 | 예산(억원) | 지원기업(개) |
| --- | ---: | ---: |
| 정부단독형 | 526.6 | 310 |
| 상생협력형 | 253 | 1,043 |
| @합계 합계 | 779.6 | 1,353 |
```

**규칙:**
- **첫 셀**에 `@합계`를 접두어로 붙임 (`@합계 합계`, `@합계 소계` 등)
- `@합계` 태그는 출력에서 자동 제거됨 → "합계"만 표시
- 합계 행은 자동으로 **Bold + 상단 이중선** 적용
- 행 위치에 관계없이 사용 가능 (중간 소계에도 OK)

### 3.9 프로세스 흐름도 (`<프로세스>`)

```markdown
<프로세스: 사업 추진절차>
사업공고(중소벤처기업부) → 신청접수(전담기관) → 선정평가(전담기관) → 원가계산(원가계산기관)
↓
협약체결(전담기관) → 솔루션 개발(컨소시엄) → 중간점검(전문가 자문단) → 최종감리(감리기관)
↓
완료점검(전담기관) ← 솔루션 실증(컨소시엄) ← 성과촉진(전담기관) ← 사후관리(전담기관)
</프로세스>
```

**규칙:**
- `<프로세스: 제목>` 으로 시작, `</프로세스>`로 종료
- 각 단계: `단계명(담당자)` 형식 (담당자 생략 가능: `단계명`만도 OK)
- `→` (우방향 화살표)로 단계 연결
- `←` (좌방향 화살표)로 역방향 행
- `↓` (아래 화살표)로 행 구분 (빈 줄도 OK)
- 각 단계는 테두리 있는 셀, 화살표는 셀 사이 연결
- **행 높이 자동 조절**: 셀 내용에 따라 높이가 자동 결정됨

### 3.10 요약표

```markdown
<요약표 시작>
 ◦ **(추진 배경)** 핵심 내용 요약
   - 세부 항목 1
   - 세부 항목 2
<요약표 끝>
```

- 내부에 `◦`, `-` 태그 사용 가능
- 전체가 테두리 있는 표 안에 들어감
- 주요 내용을 박스로 묶어 강조할 때 사용

## 4. 문서 전체 구조 템플릿

```markdown
<주제목> [보고서 제목]

□ **[첫 번째 섹션 제목]**

 ◦ **(핵심 키워드)** 주요 설명 문장

   - 부연 설명 또는 세부 항목

    * 참고/주석 (출처, 부가정보)

 ◦ **(다음 키워드)** 다른 설명 문장

<강조> 특별히 강조할 메시지

□ **[두 번째 섹션 제목]**

 ◦ **(현황)** 현황 설명

<표 제목: 데이터 표 제목>

| 구분 | 항목1 | 항목2 |
| --- | ---: | ---: |
| A | 100 | 200 |
| B | 300 | 400 |

□ **[세 번째 섹션 제목]**

 ◦ **(결론)** 결론 내용

<요약표 시작>
 ◦ **(핵심 요약)** 요약 내용
   - 요약 항목 1
   - 요약 항목 2
<요약표 끝>
```

## 5. Few-Shot 변환 예시

### 입력 (사용자가 제공하는 대충 정리된 자료)

```
보고서 제목: 스마트공장 보급 현황

1. 추진배경
- 중소기업의 스마트화 지원 필요
- 22년 5,105개 보급, 누적 30,144개

2. 주요성과
- 정부단독형: 526.6억원, 310개기업
- 상생협력형: 253억원, 1,043개기업

3. 올해 계획
- 목표: 3,420개 기업
- 예산: 1,586억원
```

### 출력 (변환기가 처리할 수 있는 MD)

```markdown
<주제목> 스마트공장 보급 현황

□ **추진 배경**

 ◦ **(스마트화 지원)** 중소기업의 **스마트화 지원** 필요성에 따라 스마트공장 보급사업 추진

   - '22년 **5,105개** 보급, 누계 **3만144개**의 스마트공장 구축을 달성

□ **주요 성과**

<표 제목: 스마트공장 보급 총괄표>

| 구분 | 예산(억원) | 지원기업(개) |
| --- | ---: | ---: |
| 정부단독형 | 526.6 | 310 |
| 상생협력형 | 253 | 1,043 |

□ **올해 계획**

 ◦ **(목표)** '23년 **3,420개** 기업 보급 목표

   - 예산 **1,586억원** 투입 계획
```

## 6. ❌ 절대 하지 말 것 (금지 규칙)

### 6.1 표준 마크다운 헤더 사용 금지

```markdown
❌ # 제목
❌ ## 소제목
❌ ### 항목
```

→ 반드시 `<주제목>`, `□`, `◦` 등 전용 태그 사용

### 6.2 들여쓰기(공백) 개수 틀리면 안 됨

```markdown
❌ ◦ 텍스트        (공백 0칸 — 파서가 인식 못함)
✅  ◦ 텍스트       (공백 1칸)

❌ - 텍스트         (공백 0칸 — DESC2가 아닌 다른 것으로 인식될 수 있음)
✅    - 텍스트      (공백 3칸)

❌ * 텍스트         (공백 0칸)
✅     * 텍스트     (공백 4칸)
```

### 6.3 표에 `<표 제목:>` 빠뜨리면 안 됨

```markdown
❌ | 구분 | 값 |       (표 제목 없이 바로 시작 — 무시됨!)
   | --- | --- |
   | A | 100 |

✅ <표 제목: 현황표>   (반드시 이 줄이 먼저)

   | 구분 | 값 |
   | --- | --- |
   | A | 100 |
```

### 6.4 빈 줄 규칙

- 각 태그 사이에 **빈 줄 1개**를 넣는다
- 표 블록과 다른 태그 사이에도 빈 줄 필요
- 연속 빈 줄 2개 이상은 불필요 (1개면 충분)

### 6.5 내용 임의 변경 금지

```
❌ 원본: "526.6억원" → 변환: "약 530억원" (반올림 금지)
❌ 원본: "'22년 1,937억원" → 변환: "작년 1,937억원" (표현 변경 금지)
✅ 원본 숫자/날짜/고유명사 그대로 유지
```

## 7. 단계별 판단 가이드 (어떤 태그를 써야 할까?)

```
원본 자료의 각 항목에 대해:

1. "이것이 보고서 전체의 제목인가?"
   → YES: <주제목>
   → NO: 다음으로

2. "이것이 큰 섹션의 시작인가?" (예: I. 추진배경, 2. 주요성과)
   → YES: □
   → NO: 다음으로

3. "이것이 특별히 강조해야 하는 핵심 메시지인가?"
   → YES: <강조>
   → NO: 다음으로

4. "이것이 단계별 절차/프로세스인가?"
   → YES: <프로세스: 제목> 블록
   → NO: 다음으로

5. "이것이 정형 데이터 (표/목록)인가?"
   → YES: <표 제목:> + 마크다운 테이블 (합계행은 @합계)
   → NO: 다음으로

6. "이것이 주요 설명 포인트인가?" (1단계)
   → YES: ◦
   → NO: 다음으로

7. "이것이 위 포인트의 부연 설명인가?" (2단계)
   → YES: - (3칸)
   → NO: 다음으로

8. "이것이 참고/주석/출처 정보인가?" (3단계)
   → YES: * (4칸)
   → NO: PLAIN 텍스트로 처리
```

## 8. 표 작성 상세 가이드

### 8.1 표로 만들어야 하는 데이터 판단 기준

- **숫자 비교 데이터** (예산, 실적, 목표 등) → 반드시 표
- **분류/항목 나열** (유형별, 지역별, 연도별) → 표 권장
- **단순 설명 나열** → 불릿(◦, -)이 더 적합

### 8.2 표 정렬 규칙

```markdown
| 텍스트 항목 | 숫자 값 | 혼합 내용 |
| --- | ---: | :---: |
```

- 텍스트(이름, 구분 등): `---` (좌측 정렬)
- 숫자(예산, 인원, 비율 등): `---:` (우측 정렬)
- 짧은 코드/기간: `:---:` (가운데 정렬)

### 8.3 열이 많을 때

열이 6개 이상이면 가독성이 떨어지므로, 가능하면:
- 표를 분리하거나
- 헤더명을 축약하되, 첫 행에 **`(단위: 억원, 개)`** 같은 설명은 ◦ 태그로 표 위에 배치

## 9. Bold(**굵게**) 사용 가이드

### 9.1 쓰는 곳

- `◦` 줄의 **(괄호 키워드)** — 예: `**(추진 배경)**`
- 핵심 숫자 강조 — 예: `**5,105개**`
- 핵심 용어 — 예: `**스마트공장**`

### 9.2 쓰지 않는 곳

- `<주제목>` — 이미 자동 Bold
- `<강조>` — 이미 자동 Bold
- 전체 문장을 통째로 Bold — 가독성 저하
