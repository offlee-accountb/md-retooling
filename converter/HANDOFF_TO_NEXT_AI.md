## 3. ⚠️ 반드시 알아야 할 함정 — "YAML은 절반만 살아있다"

`core_styles.yaml`을 고쳐도 **출력이 안 바뀌는 항목이 많다.** 실제 반영 여부:

| 항목 | YAML 반영? | 실제 정의 위치 (하드코딩) |
|---|---|---|
| 블록→스타일 ID 매핑 | ✅ | `_build_style_maps()` (L133~) |
| charPr (글자크기·폰트·자간·장평) | ❌ | `char_defs` 리스트 (≈L3027) |
| 폰트 face·familyType | ❌ | `_add_font()` (≈L2526) |
| borderFill (표/박스 색·테두리) | ❌ | `add_border_fill*()` (≈L2562~) |

**교훈:** 글자크기/자간/색을 바꾸려면 YAML이 아니라 **엔진 코드를 직접** 고쳐라.
장기 과제는 이 하드코딩들을 YAML 단일 소스로 통합하는 것(Phase 1.5 마무리).

## 5. ✅ 자간 자동 조정 — 엔진 통합 완료 (2026-07-02)

사용자의 실제 워크플로("문단이 딱 1~2줄에 떨어지도록 자간 손조정")가 엔진에 자동화되어 들어갔다.
설계·수치는 `docs/DESIGN_TARGET.md` §4 참고. 구현 위치 (`converter/md_to_hwpx.py`):

- `SPACING_*` 상수 + `_estimate_lines`/`_recommend_spacing` — want 정답셋 캘리브레이션 모델 이식.
- `compute_spacing_plan(blocks)` — pass ①: BODY/DESC2 문단별 자간 계산, (base charPr, 자간)별 동적 charPr 발급 목록.
- `build_header_xml(spacing_char_prs)` — 동적 charPr를 id 14+로 등록 (`CHAR_DEFS` 모듈 상수 뒤에 이어붙임).
- `build_section0_xml(..., spacing_plan)` — 대상 문단 run에 적용, 인라인 볼드는 볼드 변형 charPr 사용.
- **남은 것:** 실물 한글에서 눈검 (output/ 3종 재생성됨), 필요 시 WIDOW/FLOOR 정책 조정, DESC3 확대 여부.

- **2026-07-02 (눈검 1차)** 사용자 피드백: 압축은 되나 1~2음절이 다음 줄로 넘침(모델의 줄폭
  과소평가). `SPACING_SAFETY = 2`(%) 마진 도입 — 접힘 판정된 문단에만 추가 압축, 하한 −12 클램프.
- **2026-07-02 (눈검 2차, 정답셋 캘리브레이션)** 사용자가 `output/2.센터장 보고용_convert_자간재수정.hwpx`
  (자간 손수정 4문단 + 한글이 저장한 전 문단 lineseg=실제 줄수)를 제공 → 모델 재설계:
  - **원인:** paraPr `breakNonLatinWord="KEEP_WORD"` → 한글은 어절 단위 줄바꿈. 글자 단위 누적
    모델은 경계(접히기 직전) 예측이 실렌더와 어긋남 (경계 재현 0/4).
  - `_estimate_lines`를 **어절 단위 줄바꿈 시뮬레이션**으로 재작성 + `SPACING_WIDTH_SCALE=1.005`.
    검증: 적용점 103/106 + 경계 4/4 재현 (구모델 105/106 + 0/4).
  - `SPACING_SAFETY` 2→1 (모델이 정확해져 마진 축소), `SPACING_MAX_FOLD_RATIO=0.995` 가드 신설
    (접은 후 마지막 줄 예상 1.00 = 도박성 접기 거부; 정답셋에서 성공 접기는 0.98~0.99, 실패는 1.00).
  - 결과: 사용자 수정 4문단 추천 4/4 일치, 과압축 실패 2문단(−12에도 안 접힘)은 무압축으로 전환.
  - 추가 정답셋이 오면 같은 절차로 재보정: 손수정 hwpx의 lineseg(적용점) + 수정 전후 자간(경계점).
- **2026-07-02 (눈검 3차, 재수정2 반영 — 정책 확정판)** 사용자 2차 손수정 10문단 분석 결과,
  **예측 마지막 줄 점유율 >0.95 구간은 모델 불확실 구간**("접혔다" 예측이 실제론 한 단어 넘침).
  스케일 재조정으로는 해결 불가(경계 4/14가 한계) → 정책으로 해결:
  - 접기: 최소 접기 후 `SPACING_TARGET_RATIO=0.94` 이하까지 추가 압축. 하한 내 미달 시 포기
    (과압축+미접힘 방지 — "보완은" 문단이 실증 사례).
  - **너지(nudge) 신설:** 접기 대상이 아니어도 점유율 >0.95(`DANGER_RATIO`)면 0.94까지 미세
    압축(하한 `NUDGE_FLOOR=-4`). 사용자의 0→−1, 0→−3 수정이 이 케이스.
  - `SPACING_FLOOR` −12→−14 (사용자가 −13을 직접 사용).
  - 검증: 재수정2의 10문단 10/10 안전(사용자값 이상 깊이+목표 줄수), 1차 4건 회귀 ✓,
    실패 접기(−12에도 3줄) 자동 포기 ✓. 추천이 사용자 손값보다 1~3% 깊은 경향 있음 —
    "너무 조여진다" 피드백이 오면 `TARGET_RATIO`를 0.95로 올릴 것.
